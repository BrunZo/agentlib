# Project plan

You'll be given an overall goal or project. E.g. a software project or a topic to learn.
We need to split it into digestible chunks. The partition should satisfy the following requirements:

1. It MUST be complete, i.e., by acomplishing every part one should achieve the goal.
2. Each piece must be concrete / actionable, i.e. it shouldn't be vague or too big.

For planning, I recommend using Agile-like methodology (see resources).

Each of the resulting tasks should be classified according to originality / cognitive return axes (see axes.md).
Be brutally honest. The user should focus on the most original and returning tasks.
